What Each Agent Does · How The Stop-Check Governs Flow

◈ Planner

Runs once. Turns the raw app idea into a concrete spec plus an evaluation rubric — the shared contract every later agent scores and builds against.

⚙ Executor

Runs once, writes the first full draft of the single-file app from the Planner's spec. After that, the Improver takes over rewriting.

▲ Evaluator

Runs every round on the current draft, scoring it 0–100 against the rubric. Its score is what the stop-check reads — it's the gate that decides whether the round continues to Critic/Improver or breaks out to Final Reviewer.

◐ Critic

Runs only if the round doesn't stop. Goes line-by-line for concrete bugs, UX gaps and code smells the Evaluator's score doesn't capture on its own.

⟁ Improver

Runs only if the round doesn't stop. Takes the draft + Evaluator's report + Critic's issues and produces the next full draft, which flows back into the Evaluator — the loop's return edge.

◎ Memory Manager

Runs every round, distilling what changed the score up or down into short notes that get fed into the next round's Improver call, so mistakes aren't repeated.

✦ Safety Monitor

Runs every round on the draft in parallel, flagging unsafe patterns (eval, unsanitized DOM writes, external calls). A high-severity flag is surfaced in the log even though it doesn't by itself stop the loop.

⬡ Final Reviewer

Runs once, after the stop-check fires for any reason. Reads the entire round history and writes the closing quality report and recommendation — it never sees a draft mid-round.

Architecture Overview

A single browser-side orchestrator drives eight specialized system-prompted agents against one shared model endpoint (claude-sonnet-4-6 via /v1/messages). Planner and Executor run once to seed a draft; Evaluator, Critic, Improver, Memory Manager and Safety Monitor then repeat inside a while loop, with state (draft, score history, memory notes) threaded forward on every call — nothing is cached or hardcoded between rounds. A stop-check runs after every Evaluator call, in fixed priority order (plateau → threshold → hard cap), and the first condition to fire breaks the loop and routes to the Final Reviewer, which only ever sees the finished history, never a mid-round draft.

Extension Ideas
Parallel evaluatorsRun 2–3 Evaluators with different rubric weightings and average their scores to reduce single-model scoring noise.
Human-in-the-loop gatePause after each Evaluator call and let a person approve, edit, or override before Critic/Improver run.
Tool-using ExecutorGive the Executor a code-execution tool so it can actually run the HTML/JS and self-correct syntax errors before handing off.
Multi-file outputSwap the single-file constraint for a small file tree (HTML/CSS/JS) with a Dependency Agent to keep imports consistent.
Cost-aware stoppingAdd a fourth stop condition: token/dollar budget, so the loop also halts on cost, not just quality.
Adversarial CriticGive the Critic a persona (e.g. "hostile code reviewer who wants this rejected") to push harder critiques than a neutral one would.
